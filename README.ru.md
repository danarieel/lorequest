# lorequest

**Движок для текстовых квестов в Telegram с локальной нейросетью.** Сюжет написан заранее и лежит в YAML-файле («lore pack»).
Модель (Ollama, без облака и ключей) пишет только комментарии рассказчика, короткие «мостики» после свободных ходов, финальный
вердикт и свободный чат после концовки. Каждый ответ чистится и проверяется, поэтому маленькая модель не уводит историю в сторону.

## Возможности

- **Сюжет заранее, голос генерируется.** Локации и варианты написаны автором, модель не может сломать историю.
- **Защита от галлюцинаций.** Ответ чистится (эмодзи, markdown, длина) и проверяется (обязательное слово рассказчика, запрещённые шаблоны,
  никаких иероглифов), до 3 перегенераций, затем авторская заготовка.
- **Проверенные факты подставляет код.** Например, этимологии: триггер-слово в выборе игрока, а факт берётся из вашего списка.
  Модель никогда не просят вспоминать факты: маленькие модели ошибаются.
- **Свободный ход не ломает сюжет.** После своего варианта движок пишет «мостик», объясняющий, как даже «сжечь башню» ведёт к следующей сцене.
- **Игровое ощущение.** Стартовая кнопка, кнопка «дальше» с меняющимися подписями, вердикт со ссылками на реальные поступки, пасхалки,
  подсказки `/hint`, секретная концовка, свободный чат после финала, прогресс переживает перезапуск.
- **Безопасно по умолчанию.** Бот отвечает только владельцу, пока вы не откроете доступ (`access`: `owner` / `list` / `anyone`).
- **Доставка по расписанию (по желанию).** Бот сам напишет выбранному человеку в выбранное время (поздравление, событие, занятие) с повторами,
  самопроверкой при старте и уведомлениями вам.
- **Инструменты.** `tools/eval_models.py` сравнивает модели вслепую; сквозной тест прогоняет весь квест с подменёнными Telegram и моделью.

## Структура проекта

```
lorequest/
├── lorequest/            движок (чистый Python-пакет)
│   ├── __main__.py       точка входа: python -m lorequest ...
│   ├── config.py         .env + config.json + флаги -> Settings
│   ├── pack.py           загрузка и ПРОВЕРКА pack.yaml; локации, факты, пасхалки, секретная концовка
│   ├── llm.py            клиент Ollama, ретраи, чистка и валидация ответов
│   ├── bot.py            Telegram: хендлеры aiogram, FSM, клавиатуры, планировщик, доставка по расписанию
│   ├── store.py          сохранённый прогресс (JSON), переживает перезапуск
│   └── ops.py            сообщения оператору (en/ru)
├── packs/
│   ├── lighthouse/       демо-пак «The Last Light»: готическая детективная история в трёх главах
│   └── template/         шаблон с комментариями: копируйте и делайте свой мир
├── docs/pack-format.md   справочник по ключам pack.yaml
├── tests/                проверка паков и сквозной тест (Telegram и модель подменены)
├── tools/eval_models.py  сравнение моделей Ollama на одних и тех же ходах
├── .env.example          TELEGRAM_TOKEN, OLLAMA_MODEL
└── config.example.json   owner_id, recipient_id, launch_at, operator_language
```

Правило: **контент живёт в `packs/`, поведение в `lorequest/`.** Чтобы сделать новый квест, движок править не нужно.

## Запуск на Windows (PowerShell), по шагам

Нужны: Python 3.10+, [Ollama](https://ollama.com) с моделью, токен бота от [@BotFather](https://t.me/BotFather) (`/newbot`).

```powershell
cd C:\путь\к\репозиторию
python -m venv .venv
.\.venv\Scripts\Activate.ps1          # если ругается на политику: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
pip install -r requirements.txt
ollama list                           # скопируйте точное имя модели

copy .env.example .env                # ТОЛЬКО копирует файл
notepad .env                          # впишите TELEGRAM_TOKEN=... и OLLAMA_MODEL=...
copy config.example.json config.json
notepad config.json                   # owner_id = ваш Telegram ID (узнать: @userinfobot), "operator_language": "ru"

python -m lorequest --pack packs/lighthouse
```

Команды всегда выполняйте из папки репозитория. Бот запускается и ждёт: откройте его в Telegram и нажмите **/start**, квест начнётся.
По умолчанию бот отвечает только владельцу. Остановка: `Ctrl+C`, логи: `data\bot.log`.

Доступ задаётся в `config.json`: `"access": "owner"` (по умолчанию), `"list"` (владелец + `allowed_ids`) или `"anyone"` (публичный бот).
Приоритет настроек: `.env` в папке проекта > переменные окружения > `config.json` > значения по умолчанию (старая переменная из `setx`
не перебьёт токен из `.env`).

## Доставка по расписанию (по желанию)

Всё выше работает по обычному `/start`. Если нужно, чтобы бот **написал первым** в заданное время (поздравление, событие, занятие), добавьте `--deliver`.

1. В `config.json` задайте `recipient_id` и `launch_at` (локальное время ПК, формат `2026-12-31T00:00:00`).
2. Получатель заранее один раз нажимает **Start** у бота (Telegram не позволяет боту писать первым).
   Бот ответит, что дверь откроется в назначенный час, а вам напишет, совпадает ли ID.
3. `python -m lorequest --pack packs/мой_мир --deliver`, затем дождитесь сообщения «🟢». Проблемы (нет картинок, модели, не тот ID) бот
   перечислит сам. На время игры ПК, Ollama и бот должны работать. Флаг `--reset` стирает сохранённый прогресс.

## Свой мир

```powershell
copy packs\template packs\my_world -Recurse
python -m lorequest --pack packs/my_world
```

Движок проверяет пак на старте и называет неверный ключ. Справочник: [docs/pack-format.md](docs/pack-format.md).

## Выбор модели и тесты

```powershell
python tools\eval_models.py --pack packs/lighthouse модель1 модель2    # пишет eval_results.md, читайте вслепую
python tests\test_pack.py
python tests\flow_test.py
```
